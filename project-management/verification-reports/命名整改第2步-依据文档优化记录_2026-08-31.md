## 三、业界依据（可追溯来源）

| 结论 | 权威来源 |
|------|----------|
| 文件/目录名用**小写**：多数 Unix/Linux 区分大小写，小写可避免跨平台（macOS/Windows 不区分、Linux 区分）与 URL 找不到文件的问题 | Google Developer Documentation Style Guide《Filenames and file types》 https://developers.google.cn/style/filenames |
| 文件名全小写，可用下划线或连字符，但要跟随项目统一约定 | Google JavaScript Style Guide http://google.github.io/styleguide/jsguide.html |
| 多词用**连字符**：搜索引擎（Google）把连字符视为词分隔符，URL/SEO 与可读性更好 | Purdue CLA《Page and File Naming Conventions》 https://www.cla.purdue.edu/resources/digital-media/knowledge-base/best-practices/naming-conventions.html |
| Python **模块/文件名用全小写下划线 snake_case** | PEP 8 https://pep8.org/ |

> 结论：面向阅读/URL 的方法文档用小写连字符（kebab-case）；Python 及本项目脚本统一用小写下划线（snake_case）。两者适用对象不同，不冲突。
