- 目录命名基本健康（英文目录几乎全小写，中文目录仅限知识库镜像）；**问题集中在文件层**。

## 三、统一命名规范（建议稿：什么情况大小写、什么情况中文）

### 3.1 三条总原则

1. **看目录定英文大小写**：同一个目录内的文件必须同一种风格，不允许并列两套。
2. **按用途定语言**：给机器/工具/开发者看的用英文，给人阅读的课程内容与过程记录用中文；"编号/类型前缀"用英文，"标题/对象"可用中文。
3. **固定名走白名单**：社区/平台/工具链固定文件名（见 1.3）原样保留，不受下列规则约束。

### 3.2 分层规则表（L0–L6，核心）

| 层 | 适用对象 | 语言 | 大小写 / 分隔 | 示例 | 所在目录 |
|----|----------|------|----------------|------|----------|
| **L0 固定名** | 社区/平台/工具链固定文件 | 英文 | 按白名单原样 | `README.md` `LICENSE` `pre-commit` `requirements.txt` | 各处 |
| **L1 治理规范/标准/模板/台账/索引** | 长期有效、有约束力或索引性的文档 | 英文 | **UPPER_SNAKE 全大写+下划线** | `NAMING_CONVENTION.md` `TASK_STATUS.md` `REPORT_TEMPLATE.md` `DOCUMENTATION_MAP.md` | `standards/`、`templates/`、`active/` 根、`docs/` 根 |
| **L2 操作指南/工具/API/how-to** | 教做某件具体事、按流程读的文档 | 英文 | **全小写 kebab-case 连字符** | `git-workflow.md` `feishu-api.md` `video-processing.md` | `guides/`、`api/`、`tools/`、`knowledge/` |
| **L3 可执行脚本** | `.py`/`.sh`/`.js` | 英文 | **全小写 snake_case 下划线**（统一，见决策 D1） | `baidu_upload.py` `check_kb_structure.sh` | `scripts/` |
| **L4 课程知识正文** | 知识拆解、考试指导、做题记录、用户笔记 | 中文 | 固定中文名 / `类型_对象.md` | `知识拆解.md` `做题记录_税法原则.md` | `knowledge-base/`、课程目录 |
| **L5 过程产出（带时效）** | 任务/验证/同步报告、交接、检查报告 | 中文为主 | `{类型}_{对象}_{YYYY-MM-DD}.md` | `文档健康度检查报告_2026-08-31.md` | `verification-reports/`、`task-reports/`、`active/` |
| **L6 编号决策** | 架构决策记录 | 英文编号+中文标题 | `ADR-NNN-中文标题.md` | `ADR-001-文档结构优化.md` | `decisions/` |

### 3.3 目录规则

- 英文目录**一律全小写**：多词目录用 kebab 连字符（`task-reports`），单词目录直接小写（`active`、`guides`）。
- 知识库镜像目录允许中文，并分别固定：`organized-content/NN章节中文名`、`source-materials/科目-章节`（P3 落规则）。
- 课程文件系统目录（本地/网盘）与飞书节点命名沿用 `NAMING_CONVENTION.md` 已定的"双轨制"，不在本规范重复。

### 3.4 日期与编号

- 文件名内日期**统一 ISO `YYYY-MM-DD`**（可排序、与 git 日期一致）；历史紧凑 `YYYYMMDD` 作为存量保留、新增不再使用。
- 编号统一三位/两位规则：ADR 用三位 `ADR-001`，讲次用两位 `02`。

### 3.5 速查口诀

> 目录全小写、连字符分词；规范模板台账用大写、操作指南用小写连字符、脚本一律小写下划线；课程内容与过程报告用中文；固定名看白名单；同目录不混风格；日期用 YYYY-MM-DD。

### 执行与回滚步骤（每批通用）

```bash
# 1) 重命名（保留 git 历史）
git mv old/path/OLD_NAME.md new/path/new-name.md
# 2) 全局更新活跃文档中的引用（编辑器/脚本替换，跳过 verification-reports 历史快照）
# 3) 验证：断链=0、结构脚本、目录风格
# 4) 提交（pre-commit 自动校验断链/类型词）
git commit -m "refactor(命名): 批次X 统一文件命名风格"
# 回滚：git mv 改回 + revert 提交即可
```

## 六、风险、验证与缺口

- **风险**：批次 1 改名若漏改一处**真实相对链接**会产生断链——已由本会话新增的 pre-commit 断链校验在提交时硬拦，且会跑独立断链脚本双保险；历史快照正文不改，故其中旧名属"历史叙述"，不视为断链来源（它们多为反引号行内代码而非链接）。
- **验证方式**：`git ls-files` 风格复算、断链脚本=0、`check_directory_structure.sh local`、pre-commit 真实提交通过、改名文件可正常打开且引用可达。
- **不在本次范围**：`data/` 软链外的课程文件（视频/transcript/课程目录）命名由 `NAMING_CONVENTION.md` 课程章节规则与双轨制覆盖；飞书/网盘侧命名不在本地仓库，不在本审计。
- **本报告状态**：仅诊断与方案，**尚未改动任何文件名**；待 D1–D5 决策后执行。
