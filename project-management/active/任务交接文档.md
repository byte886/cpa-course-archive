## 注意事项

### 1. 必须遵守的规则
- **先读文档再执行**：每次开始任务前，必须先读AGENTS.md、README.md、WORKFLOW.md
- **文档是唯一记忆来源**：不要依赖对话记忆，重要信息必须从文档中获取
- **问题驱动更新**：发现问题立即评估是否需要更新文档
- **大任务完成后执行文档健康度检查**

### 2. 工具使用规范
- **视频下载**：用`scripts/download_decrypt.js`，不要用Chrome手动下载
- **视频压缩**：用`scripts/compress.sh`，参数H.265 CRF30
- **音频转写**：用`scripts/transcribe_pipeline.py`，FunASR方案
- **网盘上传**：用`scripts/baidu_upload.py`
- **做题**：用`scripts/answer_option.sh`（单选）和`scripts/answer_multi.sh`（多选）
- **做题记录**：必须遵循`docs/development/templates/EXAM_RECORD_TEMPLATE.md`，✓永远标在官方正确答案上

### 3. 交互注意事项
- **做题交互**：统一使用v4 JavaScript方法（`scripts/answer_multi.sh`）
- **补题流程**：未做题通过答题卡单独挑选，不要从头依次做
- **页面管理**：操作前检查页面数量，异常时重开并关多余页面
- **iTerm管理**：任务完成后立即关闭对应窗口

### 4. 敏感信息
- GitHub Token已加密存储，使用时解密
- 百度网盘Token在配置文件中
- 不要在提交中包含明文敏感信息

   - 如果用户有其他要求，则按用户要求执行
   - 如果用户没有明确要求，先总结项目状态和对应角色的建议下一步，和用户确认后再执行
5. 如果环境有问题（Chrome未登录、Playwright连接失败等），主动提示用户

**用户最简启动方式**：
- 把项目文件夹加入新对话，说角色名称即可
- 例如："开发人员"、"项目管理人员"、"测试工程师"、"产品经理"
- 不需要说完整的句子，如"作为开发人员继续"
- AI识别角色后，自动按对应角色的职责和建议下一步执行

**角色职责划分（重要）**：

| 角色 | 管理责任 | 编写责任 | 其他责任 |
|------|---------|---------|---------|
| **项目管理人员** | **统一负责所有管理工作**：目录结构设计、文档体系规划、流程管理、文档治理、目录结构一致性维护、文档关联性检查、ADR决策管理 | 项目文档、流程文档、交接文档、规范文档、ADR决策 | 项目进度管理、风险管理、质量保障、跨角色协调 |
| **开发人员** | **不负责管理**，只按项目管理人员设计的目录结构实现 | 技术文档、脚本说明、API文档、代码注释 | 功能开发、bug修复、性能优化、自动化流程实现 |
| **测试工程师** | **不负责管理**，只按项目管理人员设计的目录结构存放 | 测试文档、测试用例、bug报告、测试报告 | 功能测试、回归测试、性能测试、验证修复 |
| **产品经理** | **不负责管理**，只按项目管理人员设计的目录结构存放 | 需求文档、产品规划、用户反馈、产品路线图 | 需求分析、产品规划、用户研究、优先级排序 |

**核心原则**：
- **管理统一由项目管理人员负责**：目录结构设计、文档体系规划、流程管理、文档治理等所有管理工作，统一由项目管理人员负责
- **其他角色只负责写**：开发人员、测试工程师、产品经理只负责写自己相关的内容，不负责管理目录结构或文档体系
- **变更驱动更新**：
  - 目录结构/流程变化 → 项目管理人员负责更新相关文档和目录结构
  - 功能变化 → 开发人员负责写技术文档，项目管理人员负责检查是否需要更新目录结构
  - 测试发现bug → 测试工程师负责写bug报告，项目管理人员负责检查是否需要更新流程文档
  - 需求变化 → 产品经理负责写需求文档，项目管理人员负责检查是否需要更新项目规划
- **文档问题发现即修复**：任何角色发现文档问题都要及时修复，但管理类变更（目录结构、文档体系）需要项目管理人员统一规划
