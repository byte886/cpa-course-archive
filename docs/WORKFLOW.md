# 工作流文档

本文档记录 CPA 课程归档的完整工作流程，随实际执行持续更新。

## 总体流程

```
建目录 → 下载视频 → 下载文档 → 同步网盘 → 内容解析 → 知识库(第一阶段：初始生成) → 做题验证 → 知识库(第二阶段：迭代更新) → 任务报告
```

**知识库两阶段生成说明：**

| 阶段 | 内容 | 来源 | 输出 |
|------|------|------|------|
| **第一阶段：初始生成** | 基于讲义和视频内容生成知识拆解和考试指导 | 讲义OCR + 视频音频转写 | 初始知识库（知识拆解 + 考试指导） |
| **第二阶段：迭代更新** | 基于做题过程补充易错点、记忆口诀、真题解析、用户笔记精华 | 做题记录 + 用户笔记 + 官方解析 + 错题分析 | 更新后的知识库（补充易错点、记忆口诀、真题解析） |

**为什么需要两阶段：**
1. 知识库的来源不仅包括讲义和视频，还包括做题过程中产生的做题记录、用户笔记、官方解析等
2. 第一阶段生成初始知识库后，通过做题验证发现遗漏的知识点和易错点
3. 第二阶段将做题过程中的高价值内容整合到知识库中，使知识库更完整、更实用
4. 两阶段生成确保知识库既包含基础知识，又包含考试实战经验

每个讲座独立走完一遍流程，完成后再进入下一个。

## 1.5 Playwright 浏览器连接（所有浏览器操作的前置步骤）

### 参考文档
- [scripts/playwright_connect.sh](../scripts/playwright_connect.sh) — Playwright 连接脚本，自动检测并处理连接确认

### 连接方式
**必须使用 Extension 模式附加到用户已登录的 Chrome，禁止用 `open` 打开新窗口**（新窗口没有登录状态）。

```bash
# 方式1：使用连接脚本（推荐，自动处理连接确认）
bash scripts/playwright_connect.sh

# 方式2：手动连接
npx playwright cli -s=ga attach --extension=chrome
```

### ⚠️ 操作前必须关闭不相关的tab页（重要）

**每次开始浏览器操作前，必须先检查并关闭不相关的tab页**，避免误点击、页面混淆、内存占用。

**详细流程和命令**：参考 [docs/development/interaction-workflow.md](development/interaction-workflow.md) 第1节"页面管理原则"

**原则摘要**：
- 操作前检查tab数量，超过2个就需要清理
- 只保留当前任务需要的页面
- 异常时可以重新开新页面，但必须关掉多余的旧页面
- 适用于所有浏览器操作场景

### 第一次连接的确认流程
1. 运行连接命令后，Chrome 会自动打开"Playwright Extension"连接确认页面
2. 连接脚本会自动切换到该页面并激活 Chrome
3. **需要手动点击高顿网站标签页右侧的 "Allow & select" 按钮**（这是 Chrome 扩展的安全机制，无法完全绕过）
4. 点击后连接自动建立，**之后会被记住，不需要再次确认**

### 完全自动化（可选，推荐）
如果希望脚本自动点击 "Allow & select"，需要在 Chrome 中开启"允许 Apple 事件中的 JavaScript"：

**开启方法（只需一次）：**
1. 切换到 Chrome 窗口
2. 菜单栏 → 查看 → 开发者 → 允许 Apple 事件中的 JavaScript
3. 点击后菜单项前会出现 ✓ 标记，表示已开启

**开启后的效果：**
- 连接脚本可以自动检测连接确认页面
- 自动切换到该页面
- 自动点击高顿网站标签页的 "Allow & select" 按钮
- 完全无需人工干预

**如果不开启：**
- 第一次连接时需要手动点击 "Allow & select" 按钮
- 之后连接会被记住，不需要再次确认
- 连接脚本会自动切换到连接确认页面并提示操作

### Token 自动刷新流程（连接失败时使用）

当出现 `Failed to connect to MCP relay: WebSocket error` 或 token 过期时，需要刷新 token。

**详细流程和脚本**：参考 [docs/development/playwright-cli-guide.md](development/playwright-cli-guide.md) 第4节"Token 自动刷新流程"

**摘要**：
- Extension 状态页面：`chrome-extension://mmlmfjhmonkocbjadbfplnigmagldckm/status.html`
- 使用 AppleScript 点击刷新按钮并获取新 token
- 点击刷新后旧连接会断开，必须用 AppleScript 获取新 token
- 获取新 token 后重新设置环境变量并连接

### 常见问题
| 问题 | 原因 | 解决方案 |

## 2. 下载视频

### 参考文档
- [docs/development/video-processing.md](development/video-processing.md) — 视频处理详细指南：前置条件、加密方案逆向分析、详细操作流程、关键陷阱汇总
- [docs/development/video-processing.md](development/video-processing.md) — 视频下载、解密、压缩的完整流程和参数说明

### 2.1 捕获密钥和 m3u8

1. Playwright Extension 模式附加 Chrome（会话名 `ga`）
2. 打开课程表页，点击目标讲座的"看回放"
3. 注入 Worker hook 脚本（`scripts/capture_key.js`）
4. reload 播放器页面，等待视频开始加载
5. 切换到 1080P 分辨率（右下角按钮）
6. 从 hook 截获的通信中提取：
   - FHD m3u8 URL（含 token，会过期）
   - AES 密钥（Worker decrypt 响应前 16 字节的 ASCII 字符串）
   - IV（m3u8 中的 `IV=0x...`）

### 2.2 下载解密合并

```bash
node scripts/download_decrypt.js <m3u8_url> <key> <iv> <输出目录>
```

- 多线程下载 .ts 分片，支持断点续传
- AES-128-CBC 解密，`setAutoPadding(false)`
- 合并为 `merged.ts`
- **验证**：检查每个分片解密后首字节为 0x47（TS sync byte）

### 2.3 压缩

在 **iTerm2 单窗口**中运行，用户可直接看 ffmpeg 实时进度：

```bash
ffmpeg -i merged.ts \
  -c:v libx265 -crf 30 -preset fast \
  -x265-params "pools=N:frame-threads=4:wpp=1" \
  -c:a aac -b:a 96k \
  -tag:v hvc1 -movflags +faststart \
  video.mp4
```

参数说明：
- `-crf 30`：恒定质量因子，数值越大体积越小质量越低；30 经测试课件文字清晰、头像略糊但不影响学习
- `-preset fast`：编码速度预设，fast 在速度和压缩率间平衡
- `-b:a 96k`：音频码率 96kbps，讲课语音足够
- `-tag:v hvc1`：Apple 兼容标签，确保 QuickTime/iOS 可播放
- `-movflags +faststart`：moov atom 前置，支持流式播放

### 2.4 验证（必须执行）

```bash
ffprobe -v error -show_entries format=duration -of csv=p=0 video.mp4
```

- 时长与原始 merged.ts 一致（误差 < 1 秒）
- moov atom 存在（faststart 生效）
- 用播放器实际播放检查开头无黑屏

**方案**：阿里 FunASR（SenseVoiceSmall），开源本地方案，0成本。

- 中文 CER 8-10%，优于 Whisper

**方案**：macOS Vision 框架 OCR（系统原生免费）。

- 高顿课件 PDF 多为图片型 PDF，需 OCR
- 工具：Swift 编译的 `/tmp/ocr_vision` + PyMuPDF（200 DPI）
- 性能：116页约2分钟
- 批量脚本：`transcription/batch_ocr.sh`（后台运行 + iTerm tail -f）
- 遇到表格/公式/图表时用 AI 视觉补充识别

### 6.0 知识库内容生成流程（两阶段概览）

**第一阶段：初始知识库生成**（基于讲义和视频）

```
1. 收集来源：视频转写文字 + 讲义文档 + 讲义OCR文字
2. 核心内容整合（知识拆解）：以讲义为基础，用视频转写补充细节
3. 考试内容补充（考试指导）：从视频转写和讲义中提取考点、易错点
4. 验证和同步：验证本地文档 → 同步到飞书知识库
```

**第二阶段：知识库迭代更新**（基于做题过程）

```
1. 收集来源：做题记录 + 用户笔记/留言 + 官方解析 + 错题分析
2. 补充知识拆解：发现遗漏的知识点，补充到知识拆解
3. 补充考试指导：补充易错点、记忆口诀、真题解析、解题思路
4. 验证和同步：验证更新后的本地文档 → 同步更新到飞书知识库
```

**完整流程**：收集来源 → 内容提取 → 内容整合 → 内容验证 → 同步飞书

```
1. 收集所有来源文档
   ├── 视频转写文字（transcript.md）
   ├── 讲义文档（PDF/PPT/DOC）
   ├── 讲义OCR文字（图片中的表格、图表）
   ├── 用户留言/笔记
   ├── 做题记录和官方解析
   └── 验证报告

2. 核心内容整合（知识拆解）
   ├── 以讲义文档为基础，梳理知识点框架
   ├── 用视频转写文字补充讲解细节和例子
   ├── 用讲义OCR文字补充图片中的表格、图表
   ├── 交叉印证，冲突时以讲义为准
   └── 标注来源（讲义页码 / 视频时间点）

3. 考试内容补充（考试指导）
   ├── 从视频转写中提取考点提示、易错点提醒
   ├── 从讲义中提取例题、真题、考情分析
   ├── 从官方解析中提取解题思路、答案解释
   ├── 从用户留言/笔记中提取记忆口诀、易错点总结
   └── 从做题验证结果中补充易错点、混淆点

4. 验证和补充
   ├── 用做题验证知识库质量
   ├── 发现遗漏的知识点，补充到知识拆解
   ├── 发现易错点和混淆点，补充到考试指导
   └── 更新验证报告

5. 同步到飞书知识库
   ├── 先验证本地文档内容完整准确
   ├── 按同步流程（6.6节）同步到飞书
   └── 验证飞书知识库内容与本地一致
```

**详细流程和要求**：见 [knowledge-base-sources.md 第三节](../development/knowledge-base-sources.md)

**适用范围**：课程节点和章节节点（如01税法总论）

**必须包含**：
1. **基本信息块**：课程/章节名称、主讲老师、整理来源、适用范围、更新时间
2. **子节点目录清单**：知识拆解和考试指导两个子文档的可点击链接，每个链接附带简要说明
3. **章节概述**：简要介绍本章节的主要内容和学习目标
4. **重点内容**：列出本章节的核心知识点（3-7条）
5. **学习建议**：给出学习顺序和方法建议

**不包含**：
- 正文知识点内容（父页面只是目录，不承载知识内容）
- 重复的章节框架（子文档中已有）
- 文档维护说明（这是流程相关文档需要记录的，不放在知识库中）

**生成时机**：
- 新增章节节点时，必须同时创建父节点目录清单
- 子文档内容变更时，父节点目录清单应同步更新（如重点内容、学习建议）
- 子文档拆解时，父节点目录清单应更新，列出所有子文档的链接和说明

**详细规范和模板**：参考 `docs/development/knowledge-base-organization.md` 第1.0.1节

### 6.4 整理原则

- 按知识点而非按视频时间线组织
- 视频语音 + PPT 画面 + 讲义文档三者交叉印证
- 标注重点、考点、易错点
- 用户留言与讲义冲突时，以讲义为准

### 6.5 节点操作注意事项

- **删除节点**：`--obj-type` 必须用 `wiki`（因为是 node_token），不是 `docx`
- **重命名节点**：用 `drive +update-title`，保留同一个 node_token
- **移动节点**：用 `wiki +move`，改变父节点
- **创建节点**：用 `wiki +node-create`，指定 `--obj-type docx`

### 6.6 知识库同步流程（核心规范）

**原则：先本地，后飞书；先验证，后同步。**

```
更新本地文档 → 验证本地文档 → 同步到飞书知识库 → 验证飞书知识库
```

#### 步骤1：更新本地文档
- 所有知识库内容的变更，**必须先在本地文档中完成**
- 本地文档位置：`docs/knowledge-base/organized-content/<章节名>/`
- 包括：知识拆解.md、考试指导.md、做题思路解析.md等

#### 步骤2：验证本地文档
- 检查文档结构是否完整（Context Block、章节标题、内容组织）
- 检查内容是否准确（与讲义、视频转写、用户留言交叉印证）
- 检查是否有遗漏的知识点或易错点
- 用做题验证知识库质量（参考第7节）

#### 步骤3：同步到飞书知识库
- **禁止直接在飞书知识库中编辑内容**（除非是紧急修复）
- 同步方式（按优先级）：
  1. **飞书API**：通过API更新文档内容（推荐，可自动化）
  2. **手动复制粘贴**：打开本地文档，全选复制，粘贴到飞书文档（备选）
- 同步前确认：本地文档已验证通过，内容完整准确

#### 步骤4：验证飞书知识库
- 同步后检查飞书知识库内容是否与本地一致
- 检查格式是否正确（标题、表格、列表等）
- 检查链接是否有效（必须使用完整飞书URL，不使用相对路径）

#### 步骤5：结构检查与清理（必须执行）
同步完成后，必须执行结构检查，避免出现重复节点、错误位置、空节点等问题：

**检查项**：
1. **节点层级检查**：知识拆解和考试指导必须在章节节点下（如01税法总论），不能在课程节点下
2. **重复节点检查**：同一层级下不能有同名节点（如两个"知识拆解"）
3. **空节点检查**：所有节点必须有内容，不能只有标题
4. **父节点链接检查**：父节点（章节节点）内容中必须有子节点的完整URL链接
5. **独立文档检查**：不能有不在知识库层级中的独立文档

**清理操作**（使用API，不使用Playwright）：
- 发现重复节点：删除重复的、内容为空的或位置错误的节点
- 发现空节点：同步内容或删除
- 发现错误位置的节点：移动到正确位置或删除后重新创建

**检查命令参考**：
```bash
# 列出某节点下的所有子节点
lark-cli wiki +node-list --space-id <space_id> --parent-node-token <node_token>

# 获取节点详情（确认父节点和位置）
lark-cli wiki +node-get --node-token "<URL>"

# 删除节点（高风险操作，需--yes确认）
lark-cli wiki +node-delete --node-token "<URL>" --yes
```

#### 同步检查清单
- [ ] 本地文档已更新并验证通过
- [ ] 飞书知识库内容与本地一致
- [ ] 格式正确，无乱码或丢失
- [ ] 链接有效（使用完整URL，不使用相对路径）
- [ ] 节点层级正确（知识拆解/考试指导在章节节点下）
- [ ] 无重复节点
- [ ] 无空节点
- [ ] 父节点内容中有子节点链接
- [ ] 无独立的错误位置文档
- [ ] TASK_STATUS.md中记录了同步时间和内容

### 6.7 知识库发展与重设计原则

**何时需要重设计或扩展知识库：**
1. **新增课程**：添加新的课程章节时
2. **结构调整**：发现现有结构不合理，需要调整层级或分类时
3. **内容扩展**：需要添加新的文档类型（如思维导图、案例库）时
4. **技术升级**：飞书知识库功能更新，需要利用新功能时

**重设计原则：**
1. **向后兼容**：重设计后，旧的链接和引用应尽量保持有效
2. **渐进式迁移**：不要一次性全部重构，按章节逐步迁移
3. **记录变更**：每次重设计都要记录变更原因、内容和时间
4. **更新文档**：重设计后，同步更新WORKFLOW.md、knowledge-base-organization.md、TASK_STATUS.md
5. **验证完整性**：重设计后，验证所有内容都已迁移，无遗漏

**扩展原则：**
1. **保持一致性**：新增内容遵循现有的命名规范、结构规范、内容分工规范
2. **先试点后推广**：新的文档类型或组织方式，先在一个章节试点，验证有效后再推广
3. **补充规范**：如果扩展涉及新的规范，及时补充到knowledge-base-organization.md

**变更管理流程：**
```
发现问题/需求 → 评估影响范围 → 设计方案 → 本地试点 → 验证效果 → 全面推广 → 更新文档
```

## 7. 做题验证知识库

### 7.1 总体原则

做题验证是**验证-补充闭环**，不是一次性步骤。通过做题检验知识库是否覆盖所有考点，错题和未覆盖的知识点补充回知识库。

### 7.2 试卷类型与数量

每个章节（讲座）下有 **8套试卷**：

| 类型 | 数量 | 说明 |
|------|------|------|
| 课后练习（按考点分） | 7套 | 每个考点一套，如"税法概念"、"税法原则"、"税法要素"等 |
| 分章真题测 | 1套 | 综合所有考点的真题测试 |

**总计：8套/章节**

### 7.3 执行顺序

1. **从测试的第1课开始**，按课程顺序依次完成每个讲座的所有试卷
2. **每个讲座内**：先做7套课后练习（按考点顺序），再做1套分章真题测
3. **⚠️ 总考试触发条件（重要）**：总考试（冲刺模考卷等）必须在**所有课程/讲座学习完成后**才能做，不能在单个章节完成后就做。原因：总考试覆盖所有章节的知识点，需要所有章节的知识库都建立后才能有效验证
4. **全部考试完成后**，根据错题情况决定如何补充相应课中的知识（如果没有必要可以不补充）

**阶段划分**：
- **阶段一（单章节验证）**：每个章节完成7套课后练习+1套分章真题测，验证该章节知识库质量
- **阶段二（综合验证）**：所有章节完成后，做总考试（冲刺模考卷），验证整体知识库质量
- 当前项目处于**阶段一**（税法01章节验证），尚未进入阶段二

### 7.3.1 冲刺模考流程（阶段二，基础流程）

**⚠️ 触发条件**：所有课程/讲座的知识库建立完成后，才能进入冲刺模考阶段。

**冲刺模考组成**：
1. **视频解析**：每套模考卷有对应的视频解析，讲解试卷中的题目
2. **机考**：在视频解析后进行，模拟真实考试环境

**流程顺序**：
```
所有课程完成 → 冲刺模考视频解析（下载/压缩/转写/知识库） → 机考 → 知识库迭代更新
```

#### 视频解析处理流程

冲刺模考的视频解析需要走与一般课程视频相同的完整流程：

1. **视频下载**：在课程表页找到冲刺模考的视频解析，点击"看回放"，按视频下载流程捕获密钥、下载分片、解密合并
2. **视频压缩**：H.265 CRF 30 / preset fast / AAC 96k，在iTerm中运行
3. **完整性验证**：时长差 < 2秒，编码格式正确，可正常播放
4. **网盘上传**：上传到百度网盘对应目录
5. **讲义下载**：下载视频解析对应的讲义文档
6. **讲义OCR**：提取讲义文字
7. **视频转写**：音频转文字
8. **知识库生成**：将视频解析内容整合到知识库（主要补充考试指导部分）

**目录结构**：
```
高顿/CPA/课程库/【26考季】VIPCPA系列-税法（蔡俊峻老师）/
├── 00_开班典礼&规划方法/
├── 01_税法全面精讲01-税法总论/
├── ...
└── 冲刺模考/                    ← 冲刺模考专用目录
    ├── 税法01_视频解析/         ← 每套模考卷的视频解析
    │   ├── video.mp4
    │   ├── transcript.md

    ├── 税法02_视频解析/
    └── ...
```

### 7.5 做题流程

每套试卷：

1. 进入课程表页该讲座下的试卷
2. **⚠️ 先根据知识库的内容学习，查询相关知识点，记录查询结果，然后再应答题目（禁止凭记忆答题）**
3. 逐题作答，每道题都要：
   - **单选题**：查询知识库 → 记录正确答案 → 点击选项 → 检查蓝色圆圈标记 → 确认跳题
   - **多选题**：查询知识库 → 逐个选项验证 → 记录所有正确答案 → 逐个点击选项（每个等待1000ms）→ 检查每个选项的蓝色方框标记 → 点击"下一题"
   - **每道题做完后必须检查是否选择了对应答案（蓝色标记），确认后才能进行下一步**
4. **如果做错了**，如果系统有提示错误，可以重新做，直到完成为止
5. 记录错题和未覆盖的知识点
6. **获取全部解析**：逐题点击"下一题"遍历所有题目，获取官方解析和用户留言
7. **补题流程**（发现未做题时）：
   - 记录所有未做题编号
   - 通过答题卡依次点击未做题编号补做（不要从头依次做，避免反向取消已做题）
   - 每道补做题都要检查蓝色标记
   - **中途不交卷，完成所有未做题后才交卷**
8. 全部完成后，将错题涉及的知识点、易错点补充回知识库的"考试指导"文档
9. **如果错题是因为知识库有误，修正知识库内容**
10. 记录做题结果到任务报告

### 7.6 第一次做 vs 重新做

- **第一次做**：按上述流程完整执行
- **重新做**：即使之前做过，也要重新做一遍，确保知识库更新后仍然能覆盖所有考点
- 已完成的试卷显示"重新做题"按钮，未完成的试卷直接点击进入

### 7.7 错题补充原则

- 错题涉及的知识点如果知识库中没有，补充到"知识拆解"文档
- 错题涉及的易错点、陷阱、解题技巧，补充到"考试指导"文档
- 如果错题是因为知识库表述不准确，修正知识库内容
- 补充后记录到任务报告

### 7.8 用户留言处理

- 每道题的"笔记"区域有其他用户的留言
- 高赞留言（点赞≥5）重点整理，可能包含记忆口诀、易错点总结
- 用户留言与讲义冲突时，以讲义为准
- 有价值的用户留言补充到"考试指导"文档
