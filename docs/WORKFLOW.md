# 工作流文档

本文档记录 CPA 课程归档的完整工作流程，随实际执行持续更新。

## 总体流程

```
建目录 → 下载视频 → 下载文档 → 同步网盘 → 内容解析 → 知识库 → 做题验证 → 任务报告
```

每个讲座独立走完一遍流程，完成后再进入下一个。

## 2. 下载视频

### 参考文档
- [docs/development/video-processing.md](development/video-processing.md) — 视频处理详细指南：前置条件、加密方案逆向分析、详细操作流程、关键陷阱汇总
- [skill/SKILL.md](../skill/SKILL.md) — 视频下载、解密、压缩的完整脚本和参数说明（skill副本）

### 2.1 捕获密钥和 m3u8

1. Playwright Extension 模式附加 Chrome（会话名 `ga`）
2. 打开课程表页，点击目标讲座的"看回放"
3. 注入 Worker hook 脚本（`skill/scripts/capture_key.js`）
4. reload 播放器页面，等待视频开始加载
5. 切换到 1080P 分辨率（右下角按钮）
6. 从 hook 截获的通信中提取：
   - FHD m3u8 URL（含 token，会过期）
   - AES 密钥（Worker decrypt 响应前 16 字节的 ASCII 字符串）
   - IV（m3u8 中的 `IV=0x...`）

### 2.2 下载解密合并

```bash
node skill/scripts/download_decrypt.js <m3u8_url> <key> <iv> <输出目录>
```

- 多线程下载 .ts 分片，支持断点续传
- AES-128-CBC 解密，`setAutoPadding(false)`
- 合并为 `merged.ts`
- **验证**：检查每个分片解密后首字节为 0x47（TS sync byte）

### 2.3 压缩

在 **iTerm2 单窗口**中运行，用户可直接看 ffmpeg 实时进度：

```bash
ffmpeg -i merged.ts \
  -c:v libx265 -crf 30 -preset fast \
  -x265-params "pools=N:frame-threads=4:wpp=1" \
  -c:a aac -b:a 96k \
  -tag:v hvc1 -movflags +faststart \
  video.mp4
```

参数说明：
- `-crf 30`：恒定质量因子，数值越大体积越小质量越低；30 经测试课件文字清晰、头像略糊但不影响学习
- `-preset fast`：编码速度预设，fast 在速度和压缩率间平衡
- `-b:a 96k`：音频码率 96kbps，讲课语音足够
- `-tag:v hvc1`：Apple 兼容标签，确保 QuickTime/iOS 可播放
- `-movflags +faststart`：moov atom 前置，支持流式播放

### 2.4 验证（必须执行）

```bash
ffprobe -v error -show_entries format=duration -of csv=p=0 video.mp4
```

- 时长与原始 merged.ts 一致（误差 < 1 秒）
- moov atom 存在（faststart 生效）
- 用播放器实际播放检查开头无黑屏

## 3. 下载文档

### 3.1 获取下载链接

课程表页每个直播场次下展开"讲义"/"课件"条目：
- 点击"下载"按钮会触发 fetch 到 CDN 直链
- CDN 域名：`simg01.gaodunwangxiao.com/newoss/resources/...`
- PDF 可直接 curl 下载，无需认证

```bash
curl -L -o docs/课件.pdf -e "https://glivepro.gaodun.com/" "<CDN直链>"
```

### 3.2 文档格式

可能是 PDF、PPT、DOC 等，以实际下载为准。下载后用 `file` 命令确认格式。

### 3.3 完整性校验

- 对照课程清单（`docs/manifest.json`）核对每个讲座应有的文档数量
- 检查文件大小是否与页面显示一致
- PDF 可用 `pdfinfo` 检查页数

## 5. 内容解析

### 5.1 视频转文字

**方案**：阿里 FunASR（SenseVoiceSmall），开源本地方案，0成本。

- 中文 CER 8-10%，优于 Whisper
- VAD 加速后约 15x 实时（2.5小时视频约10分钟）
- 虚拟环境：`transcription/venv/`
- 脚本：`transcription/transcribe_pipeline.py`（单视频）、`transcription/batch_transcribe.sh`（批量）
- 在 **iTerm 中运行**（可开多个窗口并行）

**详细文档**：[development/transcription.md](./development/transcription.md)

### 5.2 文档文字提取

**方案**：macOS Vision 框架 OCR（系统原生免费）。

- 高顿课件 PDF 多为图片型 PDF，需 OCR
- 工具：Swift 编译的 `/tmp/ocr_vision` + PyMuPDF（200 DPI）
- 性能：116页约2分钟
- 批量脚本：`transcription/batch_ocr.sh`（后台运行 + iTerm tail -f）
- 遇到表格/公式/图表时用 AI 视觉补充识别

**详细文档**：[development/ocr.md](./development/ocr.md)

### 6.0 知识库内容生成流程（概览）

**完整流程**：收集来源 → 内容提取 → 内容整合 → 内容验证 → 同步飞书

```
1. 收集所有来源文档
   ├── 视频转写文字（transcript.md）
   ├── 讲义文档（PDF/PPT/DOC）
   ├── 讲义OCR文字（图片中的表格、图表）
   ├── 用户留言/笔记
   ├── 做题记录和官方解析
   └── 验证报告

2. 核心内容整合（知识拆解）
   ├── 以讲义文档为基础，梳理知识点框架
   ├── 用视频转写文字补充讲解细节和例子
   ├── 用讲义OCR文字补充图片中的表格、图表
   ├── 交叉印证，冲突时以讲义为准
   └── 标注来源（讲义页码 / 视频时间点）

3. 考试内容补充（考试指导）
   ├── 从视频转写中提取考点提示、易错点提醒
   ├── 从讲义中提取例题、真题、考情分析
   ├── 从官方解析中提取解题思路、答案解释
   ├── 从用户留言/笔记中提取记忆口诀、易错点总结
   └── 从做题验证结果中补充易错点、混淆点

4. 验证和补充
   ├── 用做题验证知识库质量
   ├── 发现遗漏的知识点，补充到知识拆解
   ├── 发现易错点和混淆点，补充到考试指导
   └── 更新验证报告

5. 同步到飞书知识库
   ├── 先验证本地文档内容完整准确
   ├── 按同步流程（6.6节）同步到飞书
   └── 验证飞书知识库内容与本地一致
```

**详细流程和要求**：见 [knowledge-base-sources.md 第三节](../development/knowledge-base-sources.md)

### 6.2 节点命名规范

- **章节名带两位序号**：`01税法总论`、`02增值税法`（方便排序）
- **开班典礼用00序号**：`00开班典礼&规划方法`
- **每个章节下固定两个子文档**：`知识拆解` + `考试指导`
- **通用方法独立节点**：`做题思路解析`放在课程库下，不放在具体章节下

### 6.3 文档内容分工

| 文档 | 内容 |
|------|------|
| **知识拆解** | 章节核心知识点（定义、分类、原则、表格），按考点组织 |
| **考试指导** | 做题技巧、易错点、记忆口诀、高频考点、典型题目 |

### 6.3.1 父节点目录清单规范

**适用范围**：课程节点和章节节点（如01税法总论）

**必须包含**：
1. **基本信息块**：课程/章节名称、主讲老师、整理来源、适用范围、更新时间
2. **子节点目录清单**：知识拆解和考试指导两个子文档的可点击链接，每个链接附带简要说明
3. **章节概述**：简要介绍本章节的主要内容和学习目标
4. **重点内容**：列出本章节的核心知识点（3-7条）
5. **学习建议**：给出学习顺序和方法建议

**不包含**：
- 正文知识点内容（父页面只是目录，不承载知识内容）
- 重复的章节框架（子文档中已有）
- 文档维护说明（这是流程相关文档需要记录的，不放在知识库中）

**生成时机**：
- 新增章节节点时，必须同时创建父节点目录清单
- 子文档内容变更时，父节点目录清单应同步更新（如重点内容、学习建议）
- 子文档拆解时，父节点目录清单应更新，列出所有子文档的链接和说明

**详细规范和模板**：参考 `docs/development/knowledge-base-organization.md` 第1.0.1节

### 6.4 整理原则

- 按知识点而非按视频时间线组织
- 视频语音 + PPT 画面 + 讲义文档三者交叉印证
- 标注重点、考点、易错点
- 用户留言与讲义冲突时，以讲义为准

### 6.5 节点操作注意事项

- **删除节点**：`--obj-type` 必须用 `wiki`（因为是 node_token），不是 `docx`
- **重命名节点**：用 `drive +update-title`，保留同一个 node_token
- **移动节点**：用 `wiki +move`，改变父节点
- **创建节点**：用 `wiki +node-create`，指定 `--obj-type docx`

### 6.6 知识库同步流程（核心规范）

**原则：先本地，后飞书；先验证，后同步。**

```
更新本地文档 → 验证本地文档 → 同步到飞书知识库 → 验证飞书知识库
```

#### 步骤1：更新本地文档
- 所有知识库内容的变更，**必须先在本地文档中完成**
- 本地文档位置：`docs/knowledge-base/organized-content/<章节名>/`
- 包括：知识拆解.md、考试指导.md、做题思路解析.md等

#### 步骤2：验证本地文档
- 检查文档结构是否完整（Context Block、章节标题、内容组织）
- 检查内容是否准确（与讲义、视频转写、用户留言交叉印证）
- 检查是否有遗漏的知识点或易错点
- 用做题验证知识库质量（参考第7节）

#### 步骤3：同步到飞书知识库
- **禁止直接在飞书知识库中编辑内容**（除非是紧急修复）
- 同步方式（按优先级）：
  1. **飞书API**：通过API更新文档内容（推荐，可自动化）
  2. **手动复制粘贴**：打开本地文档，全选复制，粘贴到飞书文档（备选）
- 同步前确认：本地文档已验证通过，内容完整准确

#### 步骤4：验证飞书知识库
- 同步后检查飞书知识库内容是否与本地一致
- 检查格式是否正确（标题、表格、列表等）
- 检查链接是否有效（必须使用完整飞书URL，不使用相对路径）

#### 步骤5：结构检查与清理（必须执行）
同步完成后，必须执行结构检查，避免出现重复节点、错误位置、空节点等问题：

**检查项**：
1. **节点层级检查**：知识拆解和考试指导必须在章节节点下（如01税法总论），不能在课程节点下
2. **重复节点检查**：同一层级下不能有同名节点（如两个"知识拆解"）
3. **空节点检查**：所有节点必须有内容，不能只有标题
4. **父节点链接检查**：父节点（章节节点）内容中必须有子节点的完整URL链接
5. **独立文档检查**：不能有不在知识库层级中的独立文档

**清理操作**（使用API，不使用Playwright）：
- 发现重复节点：删除重复的、内容为空的或位置错误的节点
- 发现空节点：同步内容或删除
- 发现错误位置的节点：移动到正确位置或删除后重新创建

**检查命令参考**：
```bash
# 列出某节点下的所有子节点
lark-cli wiki +node-list --space-id <space_id> --parent-node-token <node_token>

# 获取节点详情（确认父节点和位置）
lark-cli wiki +node-get --node-token "<URL>"

# 删除节点（高风险操作，需--yes确认）
lark-cli wiki +node-delete --node-token "<URL>" --yes
```

#### 同步检查清单
- [ ] 本地文档已更新并验证通过
- [ ] 飞书知识库内容与本地一致
- [ ] 格式正确，无乱码或丢失
- [ ] 链接有效（使用完整URL，不使用相对路径）
- [ ] 节点层级正确（知识拆解/考试指导在章节节点下）
- [ ] 无重复节点
- [ ] 无空节点
- [ ] 父节点内容中有子节点链接
- [ ] 无独立的错误位置文档
- [ ] TASK_STATUS.md中记录了同步时间和内容

### 6.7 知识库发展与重设计原则

**何时需要重设计或扩展知识库：**
1. **新增课程**：添加新的课程章节时
2. **结构调整**：发现现有结构不合理，需要调整层级或分类时
3. **内容扩展**：需要添加新的文档类型（如思维导图、案例库）时
4. **技术升级**：飞书知识库功能更新，需要利用新功能时

**重设计原则：**
1. **向后兼容**：重设计后，旧的链接和引用应尽量保持有效
2. **渐进式迁移**：不要一次性全部重构，按章节逐步迁移
3. **记录变更**：每次重设计都要记录变更原因、内容和时间
4. **更新文档**：重设计后，同步更新WORKFLOW.md、knowledge-base-organization.md、TASK_STATUS.md
5. **验证完整性**：重设计后，验证所有内容都已迁移，无遗漏

**扩展原则：**
1. **保持一致性**：新增内容遵循现有的命名规范、结构规范、内容分工规范
2. **先试点后推广**：新的文档类型或组织方式，先在一个章节试点，验证有效后再推广
3. **补充规范**：如果扩展涉及新的规范，及时补充到knowledge-base-organization.md

**变更管理流程：**

## 7. 做题验证知识库

### 7.1 总体原则

做题验证是**验证-补充闭环**，不是一次性步骤。通过做题检验知识库是否覆盖所有考点，错题和未覆盖的知识点补充回知识库。

### 7.2 试卷类型与数量

每个章节（讲座）下有 **8套试卷**：

| 类型 | 数量 | 说明 |
|------|------|------|
| 课后练习（按考点分） | 7套 | 每个考点一套，如"税法概念"、"税法原则"、"税法要素"等 |
| 分章真题测 | 1套 | 综合所有考点的真题测试 |

**总计：8套/章节**

### 7.3 执行顺序

1. **从测试的第1课开始**，按课程顺序依次完成每个讲座的所有试卷
2. **每个讲座内**：先做7套课后练习（按考点顺序），再做1套分章真题测
3. **⚠️ 总考试触发条件（重要）**：总考试（冲刺模考卷等）必须在**所有课程/讲座学习完成后**才能做，不能在单个章节完成后就做。原因：总考试覆盖所有章节的知识点，需要所有章节的知识库都建立后才能有效验证
4. **全部考试完成后**，根据错题情况决定如何补充相应课中的知识（如果没有必要可以不补充）

**阶段划分**：
- **阶段一（单章节验证）**：每个章节完成7套课后练习+1套分章真题测，验证该章节知识库质量
- **阶段二（综合验证）**：所有章节完成后，做总考试（冲刺模考卷），验证整体知识库质量
- 当前项目处于**阶段一**（税法01章节验证），尚未进入阶段二

### 7.4 参考文档（执行前必读）

| 文档 | 用途 |
|------|------|
| [`交互优化指南.md`](../knowledge-base/methodology/交互优化指南.md) | ⚠️ **必读**：做题页面的交互规律（单选自动跳题、多选需手动下一题、选项确认方法） |
| [`做题流程与方法论.md`](../knowledge-base/methodology/做题流程与方法论.md) | 做题的完整流程、API探索方向、经验总结 |
| [`做题思路解析.md`](../knowledge-base/organized-content/做题思路解析.md) | 面向学习者的通用做题思路、原则和方法 |

**产出物位置**：
- 做题记录：`docs/knowledge-base/source-materials/{课程名}/做题记录_{试卷名}.md`
- 用户笔记精华：`docs/knowledge-base/source-materials/{课程名}/用户笔记精华_{课程名}.md`
- 验证报告：`docs/knowledge-base/VERIFICATION_{课程名}_{试卷名}.md`

### 7.5 做题流程

每套试卷：

1. 进入课程表页该讲座下的试卷
2. **先根据知识库的内容学习**，然后再应答题目
3. 逐题作答，验证知识库是否覆盖相关知识点
4. **如果做错了**，如果系统有提示错误，可以重新做，直到完成为止
5. 记录错题和未覆盖的知识点
6. **获取全部解析**：逐题点击"下一题"遍历所有题目，获取官方解析和用户留言
7. 全部完成后，将错题涉及的知识点、易错点补充回知识库的"考试指导"文档
8. 记录做题结果到任务报告

### 7.6 第一次做 vs 重新做

- **第一次做**：按上述流程完整执行
- **重新做**：即使之前做过，也要重新做一遍，确保知识库更新后仍然能覆盖所有考点
- 已完成的试卷显示"重新做题"按钮，未完成的试卷直接点击进入

### 7.7 错题补充原则

- 错题涉及的知识点如果知识库中没有，补充到"知识拆解"文档
- 错题涉及的易错点、陷阱、解题技巧，补充到"考试指导"文档
- 如果错题是因为知识库表述不准确，修正知识库内容
- 补充后记录到任务报告

### 7.8 用户留言处理

- 每道题的"笔记"区域有其他用户的留言
- 高赞留言（点赞≥5）重点整理，可能包含记忆口诀、易错点总结
- 用户留言与讲义冲突时，以讲义为准
- 有价值的用户留言补充到"考试指导"文档
