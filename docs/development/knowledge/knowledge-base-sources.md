# 知识库来源清单

> **文档类型**：Reference（参考资料）
> **更新频率**：新增内容来源时
> **维护者**：AI自动维护
> **读者**：AI代理+人类

> 本文档记录知识库内容的来源，确保所有内容都可追溯、可验证。
> 原则：**本地有，则同步到知识库**。所有知识库内容必须先在本地文档中完成并验证，再同步到飞书知识库。

## 二、知识库文档与来源对应关系

### 2.1 知识拆解.md

**位置**：`knowledge-base/organized-content/<章节名>/知识拆解.md`

**内容来源**：
1. 视频转写文字（主要来源）
2. 讲义文档（交叉印证）
3. 讲义OCR文字（图片中的表格、图表）
4. 做题验证中发现的遗漏知识点（补充）

**内容组织原则**：
- 按知识点而非按视频时间线组织
- 只保留客观知识点，不包含考试指导内容
- 定义、分类、原则、表格等结构化内容
- 标注来源（视频时间点 / 讲义页码）

---

### 2.2 考试指导.md

**位置**：`knowledge-base/organized-content/<章节名>/考试指导.md`

**内容来源**：
1. 视频转写文字中的考点提示、易错点提醒
2. 讲义文档中的例题、真题、考情分析
3. 用户留言/笔记中的记忆口诀、易错点总结
4. 做题验证中发现的易错点、混淆点
5. 官方解析中的答案解释、解题思路

**内容组织原则**：
- 按"考情分析→高频考点→易错点→记忆口诀→真题回顾→学习建议"组织
- 包含做题技巧、解题思路
- 标注高频考点、易错点
- 与知识拆解互相引用

---

### 2.3 做题思路解析.md

**位置**：`knowledge-base/organized-content/做题思路解析.md`

**内容来源**：
1. 做题思路解析（通用方法）
2. 各课程做题经验总结
3. 做题流程与交互规范中的做题技巧

**内容组织原则**：
- 面向学习者的通用做题思路、原则和方法
- 不针对具体知识点，而是通用方法论
- 适用于所有CPA课程

### 2.4 做题记录数据提取规范（重要！避免把错题当答案）

**做题记录位置**：`knowledge-base/source-materials/<章节名>/做题记录_<试卷名>.md`

**做题记录模板**：`docs/development/templates/EXAM_RECORD_TEMPLATE.md`

#### 2.4.1 从做题记录中提取哪些数据（共7项）

| 数据项 | 提取位置 | 用途 | 同步到知识库 |
|--------|---------|------|------------|
| **最终正确答案** | 每题的`✓`标记和`正确答案`字段 | 验证知识库准确性，发现遗漏知识点 | 考试指导、知识拆解（补充） |
| **官方解析** | 每题的`解析`字段 | 补充考点分析、解题思路、易错点 | 考试指导 |
| **计算过程** | 计算题的`计算过程`字段 | 补充解题步骤、公式应用 | 考试指导 |
| **记忆口诀** | 每题的`记忆口诀`字段 + 文档末尾的知识点补充 | 补充记忆口诀，提高学习效率 | 考试指导 |
| **用户留言精华** | 每题的`用户留言精华`字段 | 补充易错点、解题技巧、考点总结 | 考试指导 |
| **知识点补充** | 文档末尾的`知识点补充`章节 | 补充遗漏的知识点、易错点、考点总结 | 考试指导、知识拆解 |
| **AI作答结果** | 每题的`（AI选错）`标记 | 分析AI错误原因，优化做题流程和知识库 | 不直接同步到知识库，用于流程优化 |

#### 2.4.2 重要原则：避免把错题当答案

1. **`✓`标记的是最终正确答案，不是AI选的答案**：
   - 不管AI选对还是选错，`✓`永远标在官方正确答案上
   - 如果AI选错了，在选项后标注`（AI选错）`，但`✓`仍然标在正确选项上
   - 提取数据时，只提取`✓`标记的正确答案，不要提取AI选错的答案

2. **多选题特别注意**：
   - 多选题的正确答案可能是多个，要全部提取，不能只提取AI选的那几个
   - 如果AI漏选了，也要把所有正确答案提取出来

3. **未作答的题目**：
   - 如果因为交互问题没有作答，也要记录正确答案，标注`（未作答）`
   - 提取数据时，未作答的题目也要提取正确答案和解析

4. **做题不用强求全部做对**：
   - 如实记录正确率，不用强求100%
   - 做错的题目反而更有价值，可以发现知识库的遗漏和易错点
   - 如果用户请求可以再做一遍，但不是必须

#### 2.4.3 数据提取流程

1. **收集所有做题记录**：确认该章节所有试卷的做题记录是否完整
2. **逐题提取正确答案和解析**：只提取`✓`标记的正确答案，不要提取AI选错的答案
3. **汇总知识点补充**：从所有做题记录的`知识点补充`章节汇总关键知识点
4. **整理记忆口诀和用户留言**：筛选有价值的记忆口诀和高赞用户留言
5. **对比知识库**：用提取的正确答案和知识点对比现有知识库，发现遗漏和错误
6. **补充知识库**：
   - 知识点缺失 → 补充到知识拆解
   - 易错点/陷阱/解题技巧 → 补充到考试指导
   - 知识库表述不准确 → 修正知识库内容
   - 与讲义冲突时 → 以讲义为准

#### 2.4.4 数据提取检查清单（共11项）

- [ ] 所有做题记录是否完整收集
- [ ] 每题的正确答案是否提取（只提取`✓`标记的，不是AI选的）
- [ ] 多选题的所有正确答案是否都提取（不是只提取AI选的）
- [ ] 未作答的题目是否也提取了正确答案
- [ ] 官方解析是否完整提取
- [ ] 计算题的计算过程是否提取
- [ ] 记忆口诀是否整理
- [ ] 用户留言精华是否筛选（高赞、有价值）
- [ ] 知识点补充是否汇总
- [ ] 与知识库对比，发现遗漏和错误
- [ ] 补充到知识库（知识拆解/考试指导）

## 三、来源选择流程与顺序

### 3.1 总体原则

- **所有知识库内容必须有来源依据，不能凭空编造**
- 多个来源冲突时，按优先级处理
- 重要内容标注来源（视频时间点 / 讲义页码 / 用户留言）
- 先收集所有来源，再按顺序整合，最后验证补充

### 3.2 来源优先级（从高到低）

| 优先级 | 来源类型 | 说明 | 适用文档 |
|--------|---------|------|---------|
| 1（最高） | **讲义文档** | 官方提供的讲义，内容最权威 | 知识拆解、考试指导 |
| 2 | **视频转写文字** | 老师讲解的内容，与讲义交叉印证 | 知识拆解、考试指导 |
| 3 | **讲义OCR文字** | 讲义中图片的表格、图表文字 | 知识拆解 |
| 4 | **官方解析** | 题目的官方答案和解析 | 考试指导 |
| 5 | **用户留言/笔记** | 其他用户的高赞留言、记忆口诀 | 考试指导 |
| 6（最低） | **做题验证结果** | 做题过程中发现的易错点、混淆点 | 考试指导、知识拆解（补充） |

### 3.3 来源选择顺序（按流程）

#### 第一步：收集所有来源文档

在开始整合知识库内容之前，必须先确认所有来源文档是否完整：

- [ ] 视频转写文字是否完整（`transcript.md`）
- [ ] 讲义文档是否已下载（`docs/`目录）
- [ ] 讲义OCR文字是否已提取（图片中的表格、图表）
- [ ] 用户留言/笔记是否已整理（`用户笔记精华_*.md`）
- [ ] 做题记录是否已完成（`做题记录_*.md`）
- [ ] 官方解析是否已提取

**要求**：来源文档不完整时，先补充来源文档，再开始整合知识库内容。

#### 第二步：核心内容整合（知识拆解）

按以下顺序整合知识拆解内容：

1. **以讲义文档为基础**，梳理知识点框架（定义、分类、原则、表格）
2. **用视频转写文字补充**讲解细节、例子、老师强调的重点
3. **用讲义OCR文字补充**图片中的表格、图表、流程图
4. **交叉印证**，确保内容准确（讲义和视频转写不一致时，以讲义为准）
5. **标注来源**（重要知识点标注讲义页码或视频时间点）

**要求**：
- 知识拆解只保留客观知识点，不包含考试指导内容
- 按知识点而非按视频时间线组织
- 内容必须有来源依据，不能凭空编造

#### 第三步：考试内容补充（考试指导）

按以下顺序整合考试指导内容：

1. **从视频转写中提取**考点提示、易错点提醒、老师强调的重点
2. **从讲义中提取**例题、真题、考情分析、学习建议
3. **从官方解析中提取**解题思路、答案解释、考点分析
4. **从用户留言/笔记中提取**记忆口诀、易错点总结、学习技巧
5. **从做题验证结果中补充**易错点、混淆点、考点遗漏

**要求**：
- 按"考情分析→高频考点→易错点→记忆口诀→真题回顾→学习建议"组织
- 用户留言与讲义冲突时，以讲义为准
- 记忆口诀标注来源（用户留言 / 老师讲解）

#### 第四步：验证和补充

知识库内容整合完成后，必须通过做题验证：

1. **用做题验证知识库质量**（参考WORKFLOW.md第7节）
2. **发现遗漏的知识点**，补充到知识拆解
3. **发现易错点和混淆点**，补充到考试指导
4. **更新知识库来源清单**和验证报告
5. **同步到飞书知识库**（先本地验证，后同步）

**要求**：
- 验证是必须的步骤，不能跳过
- 验证发现的问题必须及时补充
- 验证结果记录到验证报告中

### 3.4 不同文档的来源选择

| 文档 | 主要来源 | 次要来源 | 不使用 |
|------|---------|---------|--------|
| **知识拆解** | 讲义文档 + 视频转写文字 + 讲义OCR文字 | 做题验证结果（补充遗漏） | 用户留言/笔记、官方解析 |
| **考试指导** | 视频转写（考点提示）+ 讲义（例题/真题）+ 官方解析 | 用户留言/笔记 + 做题验证结果 | 讲义OCR文字（除非是例题中的图表） |
| **做题思路解析** | 通用做题方法论 + 各课程做题经验总结 | exam-workflow.md（做题流程与交互规范） | 具体知识点内容 |

### 3.5 冲突处理规则

当多个来源的内容不一致时，按以下规则处理：

| 冲突情况 | 处理方式 |
|---------|---------|
| 讲义 vs 视频转写 | **以讲义为准**（讲义是官方权威来源） |
| 讲义 vs 用户留言 | **以讲义为准** |
| 视频转写 vs 用户留言 | **以视频转写为准** |
| 官方解析 vs 用户留言 | **以官方解析为准** |
| 用户笔记 vs 知识库拆解 | **以原知识库（知识拆解）为准**（用户笔记可能存在个人理解偏差，需验证后才能修改知识库） |
| 视频转写前后不一致 | 以老师最后强调的为准，或标注"待确认" |
| 不确定时 | 标注"待确认"，后续通过做题或其他方式验证 |

**要求**：
- 冲突处理必须记录原因和依据
- 重要冲突点标注在文档中
- 不确定的内容不能作为确定知识点呈现

### 3.6 来源标注要求

| 内容类型 | 标注要求 | 示例 |
|---------|---------|------|
| 重要知识点 | 标注讲义页码或视频时间点 | "（讲义P12）"、"（视频00:15:30）" |
| 易错点和混淆点 | 标注来源（用户留言 / 做题验证） | "（用户留言，点赞12）"、"（做题验证，错误率60%）" |
| 记忆口诀 | 标注来源（用户留言 / 老师讲解） | "（用户留言，点赞8）"、"（老师讲解）" |
| 表格和图表 | 标注来源（讲义页码 / OCR提取） | "（讲义P15，OCR提取）" |
| 例题和真题 | 标注来源（讲义 / 官方解析） | "（讲义例题3-2）"、"（2023年真题）" |

**要求**：
- 标注不是必须的，但重要内容建议标注
- 标注格式统一，便于后续追溯
- 标注位置在内容末尾，用括号括起来

## 四、知识库同步流程

**原则：先本地，后飞书；先验证，后同步。**

```
更新本地文档 → 验证本地文档 → 同步到飞书知识库 → 验证飞书知识库
```

### 步骤1：更新本地文档
- 所有知识库内容的变更，**必须先在本地文档中完成**
- 本地文档位置：`knowledge-base/organized-content/<章节名>/`

### 步骤2：验证本地文档
- 检查文档结构是否完整
- 检查内容是否准确（与来源文档交叉印证）
- 检查是否有遗漏的知识点或易错点
- 用做题验证知识库质量

### 步骤3：同步到飞书知识库
- **禁止直接在飞书知识库中编辑内容**（除非是紧急修复）
- 同步方式（按优先级）：
  1. **飞书API**：通过API更新文档内容（推荐，可自动化）
  2. **手动复制粘贴**：打开本地文档，全选复制，粘贴到飞书文档（备选）
- 同步前确认：本地文档已验证通过，内容完整准确

### 步骤4：验证飞书知识库
- 同步后检查飞书知识库内容是否与本地一致
- 检查格式是否正确（标题、表格、列表等）
- 检查链接是否有效

## 五、知识库发展与重设计原则

**何时需要重设计或扩展知识库：**
1. **新增课程**：添加新的课程章节时
2. **结构调整**：发现现有结构不合理，需要调整层级或分类时
3. **内容扩展**：需要添加新的文档类型（如思维导图、案例库）时
4. **技术升级**：飞书知识库功能更新，需要利用新功能时

**重设计原则：**
1. **向后兼容**：重设计后，旧的链接和引用应尽量保持有效
2. **渐进式迁移**：不要一次性全部重构，按章节逐步迁移
3. **记录变更**：每次重设计都要记录变更原因、内容和时间
4. **更新文档**：重设计后，同步更新WORKFLOW.md、knowledge-base-organization.md、TASK_STATUS.md
5. **验证完整性**：重设计后，验证所有内容都已迁移，无遗漏

**扩展原则：**
1. **保持一致性**：新增内容遵循现有的命名规范、结构规范、内容分工规范
2. **先试点后推广**：新的文档类型或组织方式，先在一个章节试点，验证有效后再推广
3. **补充规范**：如果扩展涉及新的规范，及时补充到knowledge-base-organization.md

**变更管理流程：**
```
发现问题/需求 → 评估影响范围 → 设计方案 → 本地试点 → 验证效果 → 全面推广 → 更新文档
```

每次更新知识库内容时，按此清单检查来源文档是否完整：

- [ ] 视频转写文字是否完整（`transcript.md`）
- [ ] 讲义文档是否已下载（`docs/`目录）
