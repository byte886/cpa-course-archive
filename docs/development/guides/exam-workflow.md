# 高顿题库做题工作流

> **文档类型**：Task（操作指南）
> **更新频率**：流程变更时
> **维护者**：AI自动维护
> **读者**：AI代理

本文档记录高顿题库（GlivePro）做题自动化的流程规范和交互注意事项。通用交互流程（页面管理、补题流程）见 [interaction-workflow.md](interaction-workflow.md)。

---

## 一、检查作业情况（建目录阶段必须执行）

> **⚠️ 重要**：在开始每个讲次的任务时，必须检查该讲次是否有课后作业（"继续考"），并在任务报告中明确说明。**不允许留到任务结束后才说"待确认"**。

### 1.1 检查时机

在**建目录阶段**（查看课程表页面时）就必须检查，而不是等到做题验证阶段。

### 1.2 检查方法

1. 打开高顿教育课程表页面
2. 找到对应讲次，查看是否有"继续考"或"做作业"按钮
3. 如果有按钮，说明该讲次有课后作业，需要在后续流程中执行做题验证
4. 如果没有按钮，说明该讲次无课后作业，在任务报告中明确说明

### 1.3 常见情况

| 讲次类型 | 是否有作业 | 说明 |
|----------|-----------|------|
| 开班典礼（00） | ❌ 通常无 | 介绍性课程，无课后练习 |
| 正式章节（01+） | ✅ 通常有 | 每个章节后有课后练习 |
| 冲刺模考 | ✅ 有 | 有机考和视频解析 |

### 1.4 任务报告要求

- **有作业**：在任务报告中说明作业数量、题型、完成情况
- **无作业**：在任务报告中明确说明"本讲无课后作业，跳过做题验证和知识库第二阶段"
- **不允许**：写"待确认"或"待检查"

## 二、做题前准备

### 2.1 页面管理

通用页面管理原则（操作前检查、标签页管理、自动清理流程）见 [interaction-workflow.md](interaction-workflow.md) 第一章。

**做题场景特别注意**：
- 当前工作页：URL 中 `resState/0` 表示未完成试卷，`resState/1` 表示已完成试卷
- 优先在 `resState/0`（未完成）的页面上操作
- 重复页面：同一试卷可能同时存在未完成（resState/0）和已完成（resState/1）两个标签页

### 2.2 知识库查询（核心规范）

**做题前必须先参考知识库中的相关考点内容，禁止自己猜答案。**

**流程**：
1. 进入试卷后，先浏览所有题目，识别考点标签
2. 对于每个考点，先查阅知识库中对应的知识拆解和考试指导文档
3. 基于知识库内容作答，不要凭印象或猜测
4. 对于知识库中没有的知识点，做完题后要补充到知识库中

**知识库位置**：
- 知识拆解：`knowledge-base/organized-content/XX课程名/知识拆解.md`
- 考试指导：`knowledge-base/organized-content/XX课程名/考试指导.md`
- 做题记录：`knowledge-base/source-materials/XX课程名/做题记录_*.md`

**执行方式**：
- 可以使用`grep`命令快速搜索知识库中的相关内容：`grep -r "关键词" knowledge-base/organized-content/`
- 对于多选题，必须确认每个选项都在知识库中有对应的依据
- 对于记忆模糊的题目，必须查阅知识库，不能凭印象作答

### 2.3 考点识别与批量查询

**效率优化：批量查阅知识库**
- 进入试卷后，先快速浏览所有题目（通过答题卡逐题查看题干），识别所有考点
- 批量查阅知识库中对应的考点内容，一次性获取所有需要的知识点
- 避免每做一道题就搜索一次知识库，减少重复搜索时间

**知识库参考流程分级规则**：
- **L1 严格参考（新题目/首次做/记忆模糊）**：必须逐题查阅知识库，基于知识库内容作答，禁止自己猜
- **L2 快速确认（已做过1-2次且正确率≥80%）**：快速浏览题干，确认答案与知识库一致，如有疑问立即查阅知识库
- **L3 直接作答（已做过3次以上且连续100%正确）**：可直接作答，但交卷前必须通过答题卡检查所有题的选择状态
- **注意**：分级规则仅适用于同一套题的重复练习，新试卷必须从L1开始

### 2.4 遇到错误时的验证流程

当做题过程中发现以下情况时，必须重新做题来验证和优化流程：

1. **知识点错误**：答错题目，且知识库中已有相关记录但未参考 → 说明流程执行不到位，需要重新做题验证"做题前参考知识库"的流程
2. **知识库不完整**：答错题目，且知识库中没有相关知识点 → 先补充知识库，然后重新做题验证补充后的知识库是否有效
3. **交互问题**：点击丢失、答题卡遮挡、自动跳题异常等 → 优化交互流程后，重新做题验证
4. **流程优化**：发现新的效率提升方法或避坑经验 → 更新文档后，重新做题验证优化效果

**验证标准**：
- 重新做题的正确率应高于或等于之前的正确率
- 交互流程应更顺畅，无点击丢失或异常
- 做题时间应更短或相当

## 三、做题流程

### 3.1 单选题

- 选择选项后**会自动跳题**，无需手动点击"下一题"
- 如果选择后没有自动跳题，可能是：
  - 答题卡还打开着，遮挡了选项 → 先关闭答题卡（点击页面空白处）
  - 页面加载异常 → 刷新页面
- **命令拆分标准**：单选题每批最多3题，避免命令超时被移到后台。如果一批超过3题，应拆分成多个命令

### 3.2 多选题

- 选择选项后**不会自动跳题**，必须手动点击"下一题"
- 多个选项之间点击间隔建议 ≥ 1000ms，避免点击丢失（经测试1000ms足够，无需1500ms）
- **点击后验证选择状态**：每个选项点击后，通过snapshot检查该选项是否有选中状态（如蓝色圆圈或active class），确认成功后再点击下一个选项
- 最后一题（多选题）选择完成后，手动点击"交卷"
- **命令拆分**：多选题操作避免在一个Bash命令中包含太多sleep和点击，防止命令超时被移到后台。可以将4个选项的点击拆分成2个命令（每2个选项一个命令）

#### 2.2.1 JavaScript直接点击方法（推荐，已验证9/9全对）

**⚠️ 核心原则：**
1. **使用JavaScript直接点击选项**（通过文本内容匹配），不依赖ref——这是解决多选题ref失效的根本方法
2. **每个Bash命令只做一道题**，禁止在一个命令中做多道题
3. **每次点击后验证**：检查当前题号是否变化（单选题点击后自动跳题）或选项是否被选中

**JavaScript直接点击方法：**
```javascript
// 通过文本内容匹配找到选项元素并点击
const allElements = document.querySelectorAll('div, span, p');
for (let el of allElements) {
  if (el.textContent.trim() === 'A' && 
      el.offsetParent !== null && 
      el.getBoundingClientRect().top > 100) {
    el.click();
    return 'clicked A';
  }
}
```

**操作步骤：**
1. 阅读题目，识别考点
2. **强制查询知识库**，逐个选项验证，记录所有正确答案
3. **使用JavaScript直接点击第一个正确选项**，等待 2000ms
4. **使用JavaScript直接点击第二个正确选项**，等待 2000ms
5. （如有更多选项，重复步骤4）
6. **点击"下一题"按钮**（使用JavaScript）
7. 确认当前题号是下一题（避免跳题）

**ref失效处理原则：**
- **根本解决方案**：使用JavaScript直接点击，不依赖ref
- ref只用于单选题的第一个选项点击（因为单选题点击后自动跳题，不会有后续选项）
- 多选题必须使用JavaScript直接点击所有选项
- **命令拆分标准**：每个Bash命令只做一道题

### 3.3 答题卡操作

- **打开答题卡后必须先关闭再做题**，否则答题卡会遮挡选项，导致点击失败
- 关闭方法：点击页面空白区域（非答题卡区域）
- 通过答题卡跳题后，答题卡会自动关闭，但有时不会，需手动确认

### 3.4 补题流程

通用补题流程（原则、正确流程、未做题识别方法）见 [interaction-workflow.md](interaction-workflow.md) 第1.5节。

**做题场景特别注意**：
- 交卷前如果发现有未做题，通过答题卡单独挑选未做题作答
- 禁止从头依次重做（会导致已做题被反向点击取消选择）
- 所有未做题完成后，必须再次检查答题卡状态，确认全部已完成后再交卷

### 3.5 交卷确认与时间到处理

#### 交卷前检查流程（强制）

所有题目完成后，交卷前必须执行以下检查：
1. 打开答题卡，逐题检查是否都有选择状态
2. 对于多选题，确认所有正确选项都已选中
3. 如果发现未做题，通过答题卡单独挑选未做题作答（禁止从头依次重做）
4. 确认所有题都做完后，再点击"交卷"→"确认交卷"

#### 交卷确认

- 点击"交卷"后，如果有未做题，会弹出确认框"你还有X题未做，确定交卷吗？"
- 此时应点击"继续做题"，返回补题，不要点击"确认交卷"
- 确认所有题都做完后，再点击"交卷"→"确认交卷"

#### 时间到处理

- 考试时间到了会弹出对话框"已经到考试结束时间了哦，要立即交卷吗？"，有"立即交卷"按钮
- **直接点击"立即交卷"提交**，不要继续做题（时间到后继续做题没有意义）
- 提交后查看成绩，记录正确率和失分原因

## 四、错题处理与知识库补充

### 4.1 成绩读取规范（强制执行）

交卷后读取成绩时，必须按以下顺序读取并验证：
1. 读取"得分"字段（本次实际得分）
2. 读取"答对题数"字段
3. 读取"正确率"字段
4. 交叉验证：得分 = 答对题数（每题1分），正确率 = 答对题数 / 总题数
5. 点击"错题解析"，确认哪道题答错了
6. 记录错题详情（题目、我的答案、正确答案、解析）

**禁止行为**：
- ❌ 只读取"最高得分"就当成是本次得分
- ❌ 不查看错题解析就记录成绩
- ❌ 不交叉验证得分、答对题数、正确率三个字段

### 4.2 错题分析流程

当做题出现错题时，必须按照以下流程处理：

1. **记录错题**：将错题的题干、选项、我的答案、正确答案、解析记录到做题记录文档中
2. **分析错因**：
   - 是知识库没有相关知识点？→ 补充知识库
   - 是知识库有记录但未参考？→ 强化"做题前参考知识库"的流程
   - 是交互问题（点击丢失等）？→ 优化交互流程
3. **补充知识库**：将错题涉及的知识点补充到知识拆解和考试指导文档中
4. **做错题加练**：在成绩页面点击"错题加练"按钮，重新做错题，验证是否掌握
5. **验证效果**：错题加练的正确率应达到100%，否则重复上述流程

**错题记录位置**：`knowledge-base/source-materials/XX课程名/做题记录_*.md`

### 4.3 知识库补充原则

**新知识点补充原则（重要）**：做题过程中发现的任何新知识点（无论是考试指导相关的，还是非指导考试的），都必须补充到**知识拆解**文档中。

非指导考试的知识点（如知识背景、扩展应用、跨学科联系、实际案例等）同样需要补充，不能因为"不直接考"就忽略。知识拆解的目标是构建完整的知识体系，不仅服务于考试，也服务于知识应用、搜索和AI问答。

**冲突处理原则**：当用户留言与讲义内容冲突时，以讲义为准。

## 五、效率优化建议

### 5.1 做题效率优化

1. **批量查阅知识库**：进入试卷后先快速浏览所有题目，识别所有考点，批量查阅知识库，避免每道题都搜索一次
2. **先做单选后做多选**：单选题自动跳题效率高（每题约3-5秒），先完成所有单选题，再集中处理多选题（每题约5-8秒）
3. **多选题点击间隔1000ms**：经测试1000ms足够，无需1500ms，可节省约1分钟
4. **命令拆分**：多选题操作避免在一个Bash命令中包含太多sleep和点击，防止超时被移到后台。可将4个选项拆分成2个命令
5. **交卷前检查**：交卷前通过答题卡快速扫一遍，确认所有题都有选中状态
6. **页面保持干净**：做题前关闭多余标签页，避免内存占用和ref混乱

### 5.2 知识库检索效率优化

1. **按考点快速定位**：知识库按课程名组织，知识拆解和考试指导分开，可快速定位
2. **使用grep批量搜索**：使用`grep -r "关键词" knowledge-base/`批量搜索相关内容
3. **高频考点标记**：在考试指导文档中标记高频考点和易错题，方便快速查阅

### 5.3 交卷确认自动化

1. 点击"交卷"后，自动检测是否弹出确认框
2. 如果有未做题，点击"继续做题"返回补题
3. 如果所有题都做完，点击"确认交卷"提交
4. 提交后自动获取成绩并记录

## 六、每套题完成后的检查清单

- [ ] **每道题都先查询了知识库**（禁止凭记忆答题）
- [ ] **多选题每个选项都单独验证了**
- [ ] 所有题目都已作答（答题卡无白色未做题）
- [ ] **每道题做完后都检查了选项有蓝色标记**（单题完成检查）
- [ ] 多选题所有选项都已确认（蓝色标记）
- [ ] **补题时通过答题卡单独挑选未做题，没有从头依次做**
- [ ] **补题中途没有交卷，完成所有未做题后才交卷**
- [ ] 交卷前用答题卡检查一遍
- [ ] 交卷后查看错题，区分"知识错误"和"交互错误"
- [ ] 交互错误记录到本文档，持续优化
- [ ] **知识错误检查知识库是否有误，有误则修正知识库**
