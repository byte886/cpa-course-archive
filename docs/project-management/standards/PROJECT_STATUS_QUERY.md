# 项目状态查询协议（Project Status Query Protocol）

> **文档类型**：Governance（治理规范 — AI查询协议）
> **更新频率**：每次新增查询类型或发现新的模糊表达时
> **维护者**：AI自动维护 + 用户审核
> **读者**：AI代理（收到用户模糊查询时必须参考）

本文档定义项目状态查询的标准化协议，解决"用户表达不太准确时AI可能误会"的问题。通过定义查询意图分类、模糊表达映射表、标准响应格式，让AI能准确理解用户意图。

---

## 零、常用查询话术速查表（直接复制使用）

> **使用方法**：直接复制下面的话术发送给AI，AI会按对应意图查询并返回结构化结果。

### 📋 Q1 任务状态查询

| 你想知道 | 直接复制这句话 |
|----------|-----------------|
| 还有哪些任务要做 | `查询任务状态：还有哪些待完成的任务？` |
| 当前进度 | `查询任务状态：当前整体进度如何？` |
| 下一步是什么 | `查询任务状态：下一步应该做什么？` |
| 正在做什么 | `查询任务状态：当前正在进行哪些任务？` |

### 🐛 Q2 问题/BUG查询

| 你想知道 | 直接复制这句话 |

| 有什么风险 | `查询问题：有哪些潜在风险需要关注？` |
| 最近解决了什么 | `查询问题：最近解决了哪些问题？` |

| 需要清理什么 | `查询维护：有哪些临时文件或目录需要清理？` |

### 📄 Q4 文档/操作查询

| 你想知道 | 直接复制这句话 |
|----------|-----------------|

### 📜 Q6 决策/历史查询

| 你想知道 | 直接复制这句话 |

| 之前做了什么决定 | `查询历史：列出项目中的重要决策记录` |

### 🔄 综合查询（不确定时用这个）

| 你想知道 | 直接复制这句话 |

## 三、AI响应协议

### 3.1 意图识别流程

当收到用户查询时，AI必须按以下流程处理：

1. **识别意图**：根据模糊表达映射表，判断用户的查询属于哪一类（Q1-Q6）
2. **如果意图不明确**：主动询问用户想了解哪方面，给出2-3个选项，而不是猜测
3. **如果映射到多个意图**：询问用户想优先了解哪方面
4. **读取对应文档**：根据意图，读取对应的权威文档
5. **结构化响应**：按标准响应格式回答

### 3.2 标准响应格式

**Q1 任务状态查询的响应格式：**
```
## 当前任务状态

### 正在进行
- [任务1]：进度XX%，预计完成时间
- [任务2]：进度XX%

### 待开始
- [任务3]：前置依赖是什么
- [任务4]：预计开始时间

### 已完成（最近）
- [任务5]：完成时间，产出物位置

### 下一步
- 立即要做的事
```

**Q2 问题/BUG查询的响应格式：**
```
## 当前问题/BUG清单

### 未解决
- [问题1]：严重程度，影响范围，当前状态
- [问题2]：严重程度，影响范围，当前状态

### 已解决（最近）
- [问题3]：解决时间，解决方案

### 潜在风险
- [风险1]：发生概率，影响范围
```

**Q3 维护工作查询的响应格式：**
```
## 维护工作清单

### 定期维护（按周期）
- [每日/每周/每月]：维护内容，检查方法

### 待优化项
- [优化1]：优先级，预计工作量
- [优化2]：优先级，预计工作量

### 最近完成的维护
- [维护1]：完成时间，效果
```

**Q4 文档/操作查询的响应格式：**
```
## 相关文档和操作

### 直接相关的文档
- [文档1]：路径，简要说明
- [文档2]：路径，简要说明

### 操作步骤
1. 步骤1
2. 步骤2
3. 步骤3

### 注意事项
- 注意点1
- 注意点2
```

**Q5 项目概览查询的响应格式：**
```
## 项目概览

### 项目目标
一句话说明项目目标

### 当前阶段
- 阶段名称，完成度XX%

### 关键指标
- 已完成课程：X/Y
- 知识库章节：X个
- 已验证试卷：X套

### 最近进展
- 最近完成的重要事项

### 下一步重点
- 接下来1-2周的重点工作
```

**Q6 决策/历史查询的响应格式：**
```
## 相关决策/历史记录

### 直接相关的决策
- [ADR-XXX]：决策标题，状态，日期
  - 背景：...
  - 决策：...
  - 后果：...

### 相关历史记录
- [报告1]：路径，日期，简要内容

### 参考文档
- [文档1]：路径
```

## 四、意图不明确时的澄清话术

当AI无法确定用户意图时，应使用以下话术主动澄清：

**模板：**
```
我理解你可能想了解以下几个方面，请问你想优先了解哪一个？
1. [选项1，对应Q1]：简要说明
2. [选项2，对应Q2]：简要说明
3. [选项3，对应Q3]：简要说明
```

**示例：**
```
我理解你可能想了解以下几个方面，请问你想优先了解哪一个？
1. 任务状态：还有哪些任务要做、当前进度
2. 问题/BUG：有什么待解决的问题或异常
3. 维护工作：有什么待优化或需要定期检查的
```

## 五、维护规则

1. **新增查询类型时**：在第一节"查询意图分类"中添加新的意图ID和说明
2. **发现新的模糊表达时**：在第二节"模糊表达→意图映射表"中添加映射
3. **响应格式需要调整时**：在第三节"AI响应协议"中更新标准格式
4. **定期检查**：每次大阶段完成后，检查映射表是否覆盖了用户常用的表达
5. **AI必须遵守**：收到用户查询时，必须先参考本文档识别意图，再读取对应文档，按标准格式响应
