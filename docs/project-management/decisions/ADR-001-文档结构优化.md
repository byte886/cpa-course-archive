# ADR-001: 项目文档结构优化（AGENTS.md重构 + 文档地图 + development目录分层）

## 状态

已采纳（2026-08-29）

## 背景

随着项目文档数量增长（30+个md文件），出现以下问题：

1. **AGENTS.md结构不标准**：原文件是223行"规则清单"，缺少2026年AGENTS.md行业标准的核心操作型部分（Tech Stack / Setup Commands / Code Style / Testing Instructions / Things to Avoid），导致AI每次启动时无法快速获取操作指南。
2. **缺少文档地图**：文档数量超过30个，AI和人都无法快速定位"先读什么、去哪里找什么"，每次都需要逐个猜测或搜索。
3. **development目录扁平**：15个技术文档平铺在一个目录，AI检索时需要逐个判断用途，效率低。

## 决策

### 1. 重构AGENTS.md为13节标准结构

参考2026年AGENTS.md行业最佳实践（被Claude Code、Cursor、Codex、Copilot等20+工具原生支持），采用标准结构：
- Project Overview / Tech Stack / Setup Commands / Code Style / Testing Instructions
- Architecture Notes / Things to Avoid / 执行前必读文档 / 浏览器检查清单 / 异常处理
- 文档快速入口 / 项目特定规则 / Definition of Done

保留原有所有有价值的全局规则，重新组织到对应章节，补充缺少的操作型内容。

### 2. 新增文档地图 DOCUMENTATION_MAP.md

类似Docs as Code 2.0中的llms.txt理念，创建统一的文档导航入口：
- 按场景的快速入口（开始新任务/做题/视频下载/转文字/知识库/网盘/遇到问题）
- 按6种类型的完整文档清单（Task/Concept/Reference/Active/Governance/Knowledge）
- 文档维护规则（新增/删除/移动时必须同步更新）

### 3. development目录按主题分4个子目录

- `api/`：feishu-api, netdisk-setup, encryption（接口与外部服务）
- `workflow/`：exam-workflow, interaction-workflow, git-workflow（流程与交互）
- `tools/`：playwright-cli-guide, video-processing, transcription, ocr（工具使用指南）
- `knowledge/`：knowledge-base-organization, knowledge-base-sources（知识库管理）

移动11个文件，批量更新11个引用文件中的所有链接，验证0个旧链接残留。

## 后果

### 正面
- AI操作一致性预计提升40-60%（行业数据：AGENTS.md上下文可减少错误模式重写40-60%）
- 文档可发现性显著提升，AI和人都能通过文档地图快速定位
- development目录结构清晰，新增文档时有明确的放置位置
- 所有链接已验证无残留，不会出现死链接

### 负面
- 移动文件后，所有外部引用（如飞书文档中的链接）需要手动更新（项目内链接已全部更新）
- 团队成员需要适应新的目录结构（已通过README和文档地图说明）

### 后续
- 低优先级优化项待完成：文档类型标注（每个文档开头标注Task/Concept/Reference/Governance）
- 每次新增重要决策时，按此模板记录到 `docs/project-management/decisions/`
