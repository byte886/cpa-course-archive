# ADR-008: PROJECT_MAINTENANCE.md 文档分解为三个独立文档

> **文档类型**：Active（决策记录）
> **更新频率**：决策变更时
> **维护者**：AI自动维护
> **读者**：AI代理+人类

## 状态

已采纳（2026-08-29）

## 背景

PROJECT_MAINTENANCE.md 超过500行（552行），内容跨多个领域，出现以下问题：

1. **内容跨多个独立专业领域**：
   - 项目结构维护（结构维护原则、文件归属原则、网盘筛选、测试闭环、状态查询）
   - 文档写作指南（组织原则、分解原则、分类原则、Docs as Code、定期梳理、AI友好写作）
   - 文档优化流程（优化流程、变更驱动流程）
2. **单文档臃肿难维护**：552行的文档，AI和人都难以快速定位需要的内容。
3. **职责边界不清晰**：一个文档包含三个不同领域的内容，读者通常只需要其中一部分。
4. **维护频率差异大**：项目结构维护规则很少变更，文档写作指南偶尔更新，文档优化流程可能频繁优化。

## 决策

### 1. 按文档分解原则，将 PROJECT_MAINTENANCE.md 拆分为三个独立文档

| 文档 | 内容 | 原章节 | 行数 |
|------|------|--------|------|
| **PROJECT_STRUCTURE_MAINTENANCE.md** | 项目结构维护规范 | 第一至五章 | 174行 |
| **DOCUMENTATION_GUIDE.md** | 文档写作指南 | 第六至十一章 | 233行 |
| **DOCUMENTATION_OPTIMIZATION.md** | 文档优化流程与变更驱动 | 第十二至十三章 | 197行 |

### 2. PROJECT_MAINTENANCE.md 改为索引文档

- 只保留摘要和链接，指向三个子文档
- 从552行减少到82行
- 保留核心原则摘要，方便快速查阅

### 3. 更新所有引用

- docs/DIRECTORY_STRUCTURE.md：更新引用具体章节的地方，更新目录结构说明
- docs/DOCUMENTATION_MAP.md：添加三个新文档，更新描述
- docs/project-management/standards/README.md：添加三个新文档，更新描述
- docs/project-management/README.md：更新目录结构
- 其他引用 PROJECT_MAINTENANCE.md 的文档保持不变（因为 PROJECT_MAINTENANCE.md 现在是索引文档，仍然有效）

## 后果

### 正面
- 单文档从552行减少到82行（索引）
- 三个子文档都小于500行（174/233/197行）
- 每个文档职责清晰，独立完整，可单独阅读
- 维护频率差异大的内容分离，降低维护成本
- 所有引用已更新，验证通过

### 负面
- 移动文件后，所有外部引用（如飞书文档中的链接）需要手动更新（项目内链接已全部更新）
- 团队成员需要适应新的文档结构（已通过README和文档地图说明）
- 原来只需要读一个文档，现在可能需要读三个文档（但每个文档更聚焦）

### 后续
- 每次新增重要决策时，按此模板记录到 `docs/project-management/decisions/`
- 定期检查文档是否需要分解（超过500行或内容跨领域时）
- 完善文档变更驱动流程，添加"评估是否需要新增ADR"这一步
