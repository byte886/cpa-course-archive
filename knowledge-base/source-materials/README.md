# 原始素材目录（source-materials）

> **文档类型**：Reference（参考资料）
> **更新频率**：新增课程或试卷时
> **维护者**：AI自动维护
> **读者**：AI代理（生成知识库时参考）

本目录存放生成知识库的**原始素材**，包括做题记录、官方解析、用户留言等。

---

## 目录结构

```
source-materials/
├── <课程名>/
│   ├── 做题记录_<试卷名>.md      # 做题过程记录（临时）
│   ├── 解析与用户留言_<试卷名>.md  # 官方解析和用户留言（永久）
│   └── 用户笔记精华_<课程名>.md    # 高赞用户留言整理（永久）
└── README.md                        # 本文件
```

---

## 文件类型与保留策略

| 文件类型 | 命名模式 | 保留策略 | 用途 |
|---------|---------|---------|------|
| **做题记录** | `做题记录_*.md` | ⚠️ **临时**，知识库稳定后可删除或归档 | 记录做题过程，用于生成知识库和验证 |
| **解析与用户留言** | `解析与用户留言_*.md` | ✅ **永久保留** | 官方解析验证知识库准确性，用户留言补充知识点 |
| **用户笔记精华** | `用户笔记精华_*.md` | ✅ **永久保留** | 高赞用户留言，可能包含知识库遗漏的技巧和口诀 |

---

## 使用场景

### 1. 生成知识库（主要用途）

```
做题记录 + 解析与用户留言 + 用户笔记精华
    ↓ 整理、提炼、总结
organized-content/（知识拆解、考试指导）
    ↓ 同步
飞书知识库
```

### 2. 追溯来源

当知识库内容有疑问时，追溯到原始素材验证：
- 某个知识点是否正确？→ 查 `解析与用户留言_*.md` 中的官方解析
- 某个技巧从哪来的？→ 查 `用户笔记精华_*.md`

### 3. 补充知识库

发现知识库有遗漏时，从原始素材中补充：
- 用户留言中提到的易错点 → 补充到考试指导
- 官方解析中的详细说明 → 补充到知识拆解

### 4. 验证知识库准确性

用官方解析验证知识库内容：
- 知识库中的答案是否正确？→ 对比官方解析
- 知识库中的解释是否完整？→ 对比官方解析

## 与 organized-content 的关系

| 维度 | source-materials/ | organized-content/ |
|------|-------------------|-------------------|
| 性质 | 原材料 | 成品 |
| 内容 | 原始、未整理 | 整理、提炼、结构化 |
| 用途 | 加工、追溯、验证 | 直接使用、同步飞书 |
| 更新频率 | 每次做题后新增 | 迭代时更新 |
| 保留策略 | 部分临时、部分永久 | 永久保留 |

---

## 清理策略

### 项目迭代期（当前阶段）

- **全部保留**，方便追溯和验证
- 存储空间不是问题（每个文件几十KB）

### 知识库稳定后

- `做题记录_*.md`：可以删除或归档到 `archive/` 目录
- `解析与用户留言_*.md`：保留
- `用户笔记精华_*.md`：保留

### 判断"知识库稳定"的标准

- 连续3次做题验证正确率 > 90%
- 连续1个月没有需要补充的知识点
- 用户反馈知识库内容完整、准确

---

## 注意事项

1. **不要直接修改原始素材**：原始素材是记录，修改应在 organized-content 中进行
2. **新增试卷时自动创建**：每次做完一套题，自动生成对应的做题记录和解析文件
3. **敏感信息处理**：用户留言中可能包含个人信息，整理到知识库时注意脱敏
4. **冲突处理**：当用户留言与官方解析冲突时，以官方解析为准
